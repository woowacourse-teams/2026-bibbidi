# 서비스 UI C1 — 토큰·폰트·레이아웃 적용

적용일: 2026-10-23. 작업 이슈: [#604](https://github.com/woowacourse-teams/2026-bibbidi/issues/604). `bibbidi-design`의 Foundations를 참고해 FE 자체 구현에 반영했다. 런타임 import, 패키지 의존성, 저장소 간 자동 동기화는 없다. 이후 변경도 서비스에서 직접 검토·관리한다.

## 기준과 파일

- 기준: `bibbidi-design/src/styles/tokens.css`, Typography·Colors·Layout 문서.
- 로컬 폰트 로딩: `src/styles/fonts.css`. 토큰 값과 파일 로딩 선언을 분리한다.
- FE 값의 원본: `src/styles/tokens.css`. 문서 사이트 전용 테마와 전역 스타일은 포함하지 않는다.
- 기존 화면의 색상 이름 호환: `src/styles/colors.css`.
- 공통 반응형 바깥 여백: `src/styles/layout.css`. 최대 너비는 `components/page-container`에서 관리한다.
- 진입점의 적용 순서: fonts → tokens → 색상 별칭 → 공통 컨테이너·여백 → 전역 기본 스타일.
- 다음 표의 숫자와 HEX는 **변경 전 FE 값**이다. 새 값은 FE 토큰을 기준으로 확인한다.

CSS 미디어 조건에는 CSS 변수를 사용할 수 없어 수치를 작성한다. FE 토큰의 md를 바꿀 때는 `shared/responsive.ts`, CSS의 모바일/데스크톱 조건, 해당 경계를 사용하는 테스트를 함께 변경한다. lg/xl은 공통 값만 준비했으며 기존 화면의 내부 보조 중단점(390·520·600·1000·1199·1200 등)을 일괄 치환하지 않았다.

태블릿의 상세 오버레이, 데스크톱에서 본문 최소 너비를 확보한 뒤 상세를 병렬로 여는 동작, wide 3열 전환은 C3·C6 및 각 화면 구현에서 다룬다. C1은 공통 기반 적용이며 화면 개편 전체의 완료를 뜻하지 않는다.

## 검증

- `pnpm build`, `pnpm lint` 통과. `pnpm test`: 97개 파일, 1,156개 테스트 통과.
- Chrome에서 게스트·로그인 응답을 모킹해 320·390·760·767·768·1024·1279·1280·1439·1440px을 확인했다. 공통 헤더의 겹침·가로 넘침과 모바일 탐색 전환을 검사했다.
- Pretendard·Nunito 로컬 로딩, Gold 역할색, 문서 테마 미포함을 확인했다.
- 상세를 연 채 md 경계를 왕복했을 때 선택 항목이 유지되고 레이어/패널이 전환되는지 확인했다. 소수점 너비의 iframe에서도 CSS와 JS의 미디어 판정이 일치했다.
- 빌드에는 자산·진입 번들 크기 경고가 남아 있다. Pretendard 단일 WOFF2는 약 2MB이며 서브셋 최적화는 별도 작업이다.
- 실제 서버의 로그인·저장·일정 변경은 후속 흐름 검증 범위다.

## 책임·중복 점검

- 폰트 자산 로딩(`fonts.css`), 디자인 값(`tokens.css`), 이전 색상 이름 호환(`colors.css`), 공통 컨테이너·반응형 여백(`layout.css`)을 구분했다.
- 로그인 페이지의 효과 없는 데스크톱 여백 재선언을 제거했다. 랜딩 모션의 중복 중단점·헤더 높이 판정은 실제 헤더 높이를 읽는 공통 계산으로 바꿨다.
- 모바일 동작 테스트는 `MOBILE_LAYOUT_MEDIA_QUERY`를 가져다 사용한다. CSS의 미디어 조건에 필요한 숫자는 유지한다.
- 현재 참조가 없는 T1~T4·T6~T7, 일부 레이아웃 너비·그리드 토큰은 디자인 기준의 공통 값으로 유지한다. 개별 화면에 이 값을 적용하는 실행 코드는 추가하지 않았다.
- 기존 브랜드 글자 별칭은 서비스와 랜딩 AI 예시에서 사용 중이므로 유지한다.
- `tsc --noEmit --noUnusedLocals --noUnusedParameters`를 통과했다. 실제 헤더 높이가 바뀔 때 랜딩 이동 위치가 함께 바뀌는 회귀 테스트를 추가했다.


## 체크리스트 Layout 후속 적용 — #635

공통 `components/page-container`와 `components/workspace-layout`을 FE에서 관리하고 체크리스트에 먼저 적용했다. 디자인 시스템의 구현을 참고했으며 저장소 간 import나 패키지 의존성은 추가하지 않는다. C1에서 미뤘던 체크리스트 본문·카테고리·상세 너비를 기존 `--layout-*` 토큰에 맞췄다.

- PageContainer는 최대 너비와 뷰포트별 바깥 여백을 담당한다. 후속 #642에서 기존 헤더의 `.service-page-container`도 PageContainer로 통일했다.
- `useWorkspaceLayout`은 뷰포트 중단점과 ResizeObserver로 확인한 실제 본문 너비를 함께 판정한다. WorkspaceLayout은 그 결과에 따라 탐색·본문·보조 슬롯을 배치한다. 레이아웃 측정과 화면의 레이어 동작을 연결할 수 있도록 FE에서는 훅을 별도로 제공한다.
- 카테고리는 상단 가로 탐색을 기본으로 하고, xl 이상에서 카테고리와 본문 최소 너비를 확보하면 측면에 둔다. 보조 영역은 lg 이상이면서 본문 최소 너비·간격·패널 너비를 확보할 때만 병렬 배치한다.
- 모바일 상세 바텀시트·작성 전체 화면을 유지한다. 태블릿과 너비가 부족한 데스크톱에서는 오른쪽 오버레이를 사용한다. 할 일 추가·일정 추가/수정에도 같은 전환을 적용한다.
- 선택·작성값·URL은 기존 기능 컨트롤러가 관리한다. 오버레이는 기존 DOM 기반 확인창과 함께 동작하도록 구성하고 배경 조작·페이지 스크롤을 막는다. 닫기·저장 중 제한·변경 버리기 정책은 기존 컨트롤러에 위임한다.
- 목록은 기존 서비스 본문에서 스크롤하고, 병렬 패널은 화면에 남아 내부 본문을 스크롤한다. 병렬 패널 높이는 카테고리를 포함한 실제 시작 위치와 스크롤 위치에서 계산한다. 서비스 레이아웃은 병렬 패널의 왼쪽 경계를 측정해, 중앙 정렬 바깥 여백까지 피드백 버튼의 예약 공간에 반영한다.

CSS의 md·lg 조건을 바꾸면 관련 CSS와 공통 responsive.ts를 함께 맞춘다. WorkspaceLayout의 너비 판정은 CSS에서 읽은 px 레이아웃 토큰을 사용한다. 목록 행과 폼 내용의 디자인 교체는 이 작업에 포함하지 않는다.


#635 검토 후 모달의 스크롤 잠금·배경 비활성화·초점 이동·가두기·복귀를 `shared/modal/useModalEnvironment`에 모았다. BottomSheet와 체크리스트 오버레이가 스크롤 잠금 수명을 공유하며, 서비스 레이아웃은 `data-modal-scope`·`data-modal-background`로 배경 경계를 제공한다. 폼의 Escape·취소·검증은 폼이 담당하고, 부모 레이어는 같은 Escape를 다시 처리하지 않는다. PageContainer는 기존 `--service-page-margin`을 재사용해 중단점별 여백 정의를 한곳에 유지한다. 상세·할 일 작성에서 사용하지 않는 이전 sticky·고정 높이는 제거했으며, 캘린더에서도 사용하는 일정 작성의 기본 스타일은 유지한다.

## AppLayout 후속 적용 — #642

`bibbidi-design`의 최초 배경 규격 `09dce5c`와 후속 헤더·스크롤 규격 `ac1714f`를 기준으로 `components/app-layout`을 FE에서 직접 관리한다. ServiceLayout과 AuthLayout의 최상위 요소에 적용하며, 전체 너비·최소 화면 높이(100vh 폴백과 100dvh)·배경·기본 글자색과 헤더 배치를 담당한다. 표준 div 속성과 ref는 실제 최상위 요소에 전달한다.

앱 배경 토큰 `--color-bg-layer-basement`는 크림색에서 밝은 회색 `#F9FAFB`로 변경했다. 기본 표면 토큰 `--color-bg-layer-default`는 흰색을 유지한다. 공통 토큰을 참조하는 랜딩 일부 표면에도 새 배경색이 적용되며, 랜딩 전용 구성은 유지한다.

ServiceLayout은 AppLayout의 `header` 슬롯에 기존 AppHeader를 넣고 `sticky`·`fade`·`contained`를 사용한다. 화면 높이 안에서 AppLayout 자체가 스크롤되며 본문이 헤더 뒤로 지나간다. 기존 본문 div의 별도 스크롤은 제거했다. AuthLayout은 BrandHeader를 같은 슬롯에 넣고 `sticky`·`fade`·`document`로 문서 전체 스크롤을 유지한다. 두 헤더의 배경·구분선과 BrandHeader의 별도 sticky는 제거해 표면과 배치를 AppLayout으로 모았다.

실제 헤더 높이는 ResizeObserver로 측정하고, 미지원 환경에서는 창 크기 변경 시 다시 계산한다. 서비스의 경로 변경 시 초기화와 패널 예약 공간 측정은 AppLayout ref를 사용한다. 모달은 범위 요소 자체가 스크롤 영역인 경우도 찾아 잠그고, 병렬 상세 패널은 측정한 헤더 높이 아래에 고정하며 높이 변경도 반영한다. 하단 탐색의 본문 여백은 유지하고 스크롤 여백은 새 스크롤 영역에 적용했다. PageContainer는 너비·여백, WorkspaceLayout은 영역 배치를 담당하며 배경을 추가하지 않는다.

서비스·인증 화면은 `hideScrollBar`를 켜서 페이지 스크롤바를 숨긴다. 휠·터치·키보드 스크롤과 앵커 이동, 모달의 스크롤 잠금은 유지한다. contained는 AppLayout 자체에, document는 해당 AppLayout이 있는 문서에만 적용되며 패널·메뉴 내부의 스크롤바는 변경하지 않는다.

서비스 레이아웃은 `--service-content-height`로 헤더와 모바일 하단 독을 제외한 본문 높이를 제공한다. 내부 스크롤이 필요한 준비 로드맵은 자신의 높이에 이 값을 사용하며 상위 `.service-layout__content`를 직접 덮어쓰지 않는다. 카테고리 변경 시 목록 스크롤만 초기화하는 동작은 유지한다. 하단 독의 본문 예약 여백과 스크롤 여백은 `--service-bottom-inset`을 공유한다.

병렬 패널의 sticky 위치와 측정 높이는 WorkspaceLayout의 내부 래퍼에 적용한다. 높이 훅은 래퍼의 실제 시작 위치와 CSS가 계산한 sticky top을 읽으며 헤더 높이·간격 계산식을 중복하지 않는다. 그리드 끝에서 sticky가 위로 밀릴 때도 높이가 늘어나지 않도록 top을 하한으로 사용한다. Checklist는 해당 공간 안의 내용과 오버레이·바텀시트만 구성한다. 두 헤더는 PageContainer의 wide 규격을 재사용하고 이전 컨테이너 CSS는 제거했다.

## 체크리스트 Panel·PanelOverlay 적용

디자인 시스템의 `Panel`·`PanelOverlay`를 서비스의 `components/`에 반영했다. 저장소 간 직접 import 대신 기존 공용 컴포넌트와 같은 방식으로 관리한다.

- 상세·작성의 헤더, 본문 스크롤, 하단 액션은 `Panel`이 제공한다. 전체 제목 편집 영역은 `Panel.Header.heading`으로 전달해 heading과 form이 중첩되지 않게 한다. 패널 본문의 스크롤바는 숨기고 휠·터치·키보드 스크롤은 유지한다.
- `WorkspaceLayout`이 병렬 배치를 결정하며, 좁은 화면의 우측 패널과 모바일 전체 화면 작성은 `PanelOverlay`를 사용한다. 모바일 상세는 기존 `BottomSheet`를 유지한다.
- `ChecklistForeground`에는 서비스 스크롤 영역과 제목 ID, 닫기 정책을 공용 레이어에 연결하는 코드만 남긴다. 체크리스트 전용 배경막·위치·그림자·모달 구현은 제거했다. 모달은 네이티브 top layer가 배경 접근을 차단하며, 본문 스크롤 잠금은 공용 컴포넌트가 소유한다.
- 확인창이나 날짜 선택기가 열린 상태로 반응형 배치를 전환해도 하위 모달이 상위 패널보다 나중에 열린다. 확인창이 떠 있을 때는 재마운트된 폼이 제목 입력으로 초점을 가져가지 않는다. 작성값은 기존 컨트롤러에 보관하고, 종료 후 초점 복귀는 화면의 기존 정책을 유지한다.
- 일정이 없는 상세는 별도 테두리 박스 대신 `Result`를 사용한다. 제목은 일정 섹션 아래의 h4로 제공한다.

체크리스트 테스트와 반응형 검증 화면에서 병렬·우측·전체 화면 전환, 제목·날짜 유지, 중첩 레이어 Escape, 취소 확인, 저장 후 반영, 초점 복귀와 배경 스크롤 잠금을 확인했다.

### 닫힘 전환 보완

오버레이를 닫을 때는 선택·작성 상태가 종료돼도 마지막으로 표시한 본문을 `onExited`까지 유지한다. 확인창이 열린 내용은 퇴장용으로 보관하지 않으며, 패널과 배경막의 퇴장이 모두 끝난 뒤 배경 스크롤과 목록 초점을 복원한다. 바텀시트의 드래그 닫기는 끌어 내린 위치에서 이어서 퇴장하고, 다시 열 때 위치를 초기화한다. 진입 중에 닫거나 퇴장 중에 다시 열어도 현재 변환 위치에서 애니메이션을 이어 간다.

### 책임 분리와 구형 레이어 정리

`Dialog`·`PanelOverlay`·`BottomSheet`는 `shared/modal/useNativeModalLifecycle`에서 네이티브 모달 수명, 애니메이션 완료, 스크롤 잠금과 초점 복귀를 공유한다. `useVisualViewport`는 키보드 표시 영역을 관리하며 퇴장 중에는 마지막 크기를 유지한다. 낮은 레이어가 반응형 전환으로 새로 열려도 기존 확인창의 순서와 초점을 보존한다.

퇴장 중 레이아웃 유지와 마지막 표시값 보관은 `useLayerPresence`·`useExitSnapshot`, 서비스 스크롤 영역 탐색은 `usePageScrollContainer`로 분리했다. 화면은 닫기·저장·취소 확인 정책과 컨트롤러 연결만 소유한다. 드래그 닫기를 호출부에서 거절하면 시트가 원래 위치로 돌아오고, 모바일 날짜·시간 선택기는 퇴장이 끝날 때까지 본문을 유지한다.

준비 로드맵의 보기 선택과 모바일 피드백은 공용 `BottomSheet`로 통일했다. 홈의 로그인 안내·일정 상세는 `Dialog`를 사용하고 이동 액션은 `Button.Link`로 실제 링크 의미를 유지한다. 이전 `shared/bottom-sheet`, `useModalEnvironment`, `usePageScrollLock`, `ChecklistModalDialog`와 전용 셸 스타일, 사용하지 않는 배경·모바일 속성은 제거했다. 기존 #635 기록의 모달 훅과 배경 표시는 이 구현으로 대체된다.

## Accordion 동작과 체크리스트 표현 분리 — #676

`bibbidi-design`의 [Accordion 조합 구조](https://github.com/byunghyunkim0/bibbidi-design/pull/3), 기준 커밋 `9be5c25`를 FE에서 직접 관리한다. 저장소 간 import나 새 패키지 의존성은 추가하지 않는다.

- `AccordionPrimitive.Root`·`Item`·`Header`·`Trigger`·`Content`는 외형 CSS 없이 펼침 상태, 키보드 탐색, 접근성 연결과 외부 제어로 접힌 본문의 초점 복귀를 담당한다. 접힌 본문은 DOM에 남겨 입력값을 유지하며, 사용처의 display 스타일과 관계없이 숨긴다.
- 표준 `Accordion`·`Accordion.Item`은 같은 기본 요소를 사용하고 기존 제목·설명·장식 요소 API와 외형을 유지한다. 준비 요약은 기존 API를 그대로 사용한다.
- 체크리스트의 `ChecklistGroup`은 기본 요소를 조합하고 완료 개수·진행률·번호·헤더 높이·여백을 feature 안에서 관리한다. 진행률은 제목 버튼 밖에 배치하며, 해당 위치를 눌러도 뒤의 헤더 버튼이 동작한다.
- 공용 Accordion의 `summary`·`triggerRef` 속성과 요약 배치·패딩 확장을 제거했다. 상세 종료 후 초점 복귀는 `AccordionPrimitive.Trigger`의 표준 ref로 연결한다. 체크리스트 CSS는 공용 Accordion 클래스나 변수를 덮어쓰지 않는다.

## 캘린더 일정 추가 폼 공용 UI 적용 — #679

캘린더와 체크리스트가 같은 일정 컨트롤러를 사용하므로, 체크리스트 도메인의 `AppointmentForm`에서 입력 UI를 공유한다. 제목·장소·메모는 TextField·TextArea, 날짜·시간은 PickerField를 사용한다. 날짜 범위는 1~9999년, 시간은 1분 단위로 기존 요청 형식을 유지한다. 화면별 제목·복귀 문구·ID를 호출부에서 전달하고, 체크리스트의 변경 버리기 확인과 캘린더의 즉시 취소 정책은 기존처럼 각 화면에서 관리한다.

캘린더의 직접 구현한 dialog와 초점 가두기·입력·버튼 스타일을 제거하고 PanelOverlay·Panel·TopNavigation·Button을 사용한다. 데스크톱은 우측 패널, 모바일은 전체 화면이며 같은 폼 DOM을 유지해 화면 크기 변경 시 작성값을 보존한다. 저장 중에는 닫기를 막고, 날짜·시간 선택기의 Escape는 선택기에서 처리한다. 퇴장 동안 마지막 입력 화면과 스크롤 잠금을 유지하고 종료 후 선택을 해제한다.

진입 시점의 초점 대상을 레이어 열기 전에 기록해 취소 후 복원한다. 저장 후 해당 버튼이 사라지면 캘린더 제목으로 초점을 이동한다. 일정 생성·분석 이벤트·저장 후 목록 조회와 날짜 이동, 조회만 실패한 경우의 조회 재시도는 기존 컨트롤러 정책을 유지한다. 디자인 시스템 변경이나 새 패키지 의존성은 추가하지 않는다.

## 단일 로드맵과 단계 상세

로드맵의 ‘내 로드맵 / 전체 단계’ 전환과 별도 개인 로드맵 렌더러를 제거했다. 카탈로그의 모든 단계를 순서대로 유지하고, 카드에 담은 개수·완료 개수·다음 할 일을 표시한다. 완료율은 해당 단계에 내가 담은 항목을 분모로 계산하며 ‘내 할 일 완료’로 범위를 명시한다. 게스트는 기존 로컬 담기를 유지하고 완료율을 표시하지 않는다. 현황 조회 실패는 준비 전이나 0%로 대신하지 않고 재시도를 제공한다. 사용자가 직접 작성한 항목은 체크리스트에서 관리하며 카탈로그 단계에 임의로 배정하지 않는다.

카드 전체는 단계 상세를 여는 버튼이고 카드 안에 완료 체크나 추가 버튼을 중첩하지 않는다. 데스크톱 상세는 Dialog, 모바일은 BottomSheet이며 ListHeader·ListRow·Badge·Button을 조합한다. 전체 목록에서 담은 상태를 구분하고, 개별·전체 추가와 실패 후 재시도를 제공한다. 저장 중에는 중복 실행과 닫기를 막는다. 일정·완료 관리는 클라이언트 탐색으로 체크리스트에 연결한다. AI 추가 결과는 전역 채팅에서 안내하며 아래의 전역 AI 구성으로 대체한다.


## 로드맵 콘텐츠형 배치와 전역 AI

로드맵의 고정 AI 영역과 전용 실행 버튼을 제거했다. 바깥 PageContainer는 wide(최대 1280px)를 사용해 브레드크럼·제목·현황의 위치를 체크리스트와 맞춘다. 카테고리 탭과 단계 카드 본문은 content(최대 1040px)로 가운데 정렬하고, 탭 목록은 본문의 왼쪽 기준선에 맞춘다. 중첩 PageContainer로 바깥 여백을 다시 적용하지 않고 본문 래퍼에 공통 너비 토큰을 사용한다. 단계 카드는 본문 너비 1040px 이상에서 3열, 640px 이상에서 2열, 모바일에서는 1열이다. 데스크톱 카드 간격은 20px, 카드 내부 여백은 16px로 두어 3열에서 카드 너비 약 333px을 확보한다. 제목은 줄바꿈해 전체를 유지하고, 카드 높이는 내용과 같은 줄의 가장 긴 카드에 맞춘다. 전역 AI 실행 버튼은 ServiceLayout의 AppHeader actions에 한 번 제공한다. 기본은 닫혀 있으며 넓은 화면에서는 우측 레이어, 1024px 미만에서는 전체 화면으로 연다. 대화와 입력·추천·스크롤은 같은 세션 DOM에서 유지하고 페이지 이동이나 열고 닫기로 초기화하지 않는다. 계정이 바뀌거나 서비스 레이아웃을 떠나면 이전 세션을 해제한다.

전역 채팅은 현재 화면명(로드맵·체크리스트·캘린더·홈)을 표시하고, 전송 시 해당 화면명을 질문과 함께 전달한다. 선택한 항목이나 날짜를 자동으로 전달하는 기능은 포함하지 않는다. 재시도는 실패한 질문의 원래 화면명을 유지한다. 추천 추가 성공 시 현재 페이지와 채팅을 유지하고, 사용자가 ‘추가한 일 보기’를 선택하면 저장된 항목의 체크리스트 상세로 이동한다. 실패·중복에는 새 성공 결과를 만들지 않는다. 공용 네이티브 모달 수명과 스크롤 잠금·초점 복귀를 사용하며 원래 로드맵의 타이핑·자동 이동 연출은 제거했다.

전역 AI 전환 이후 이전 docked·모바일 전용 AI 표시와 roadmap 출처의 체크리스트 닫기 정책을 제거했다. 로드맵 탭·모달은 공통 Tab·PanelOverlay를 사용하며, 체크리스트 Panel은 contained 옵션을 사용한다. 브레드크럼은 제품 공용 조합으로 묶고 로드맵 표시 모델은 한 경로로 통합했다. AI 글자 크기·행간은 공통 타이포그래피 토큰을 사용하며 캘린더의 오류·안내는 T6로 표시한다.
