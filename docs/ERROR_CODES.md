# Bibbidi 오류 코드

## 규칙

- 오류 ID는 HTTP 상태 코드와 독립적인 3자리 숫자다.
- 오류 ID는 의미별 구간으로 관리하며, enum 선언 순서나 `ordinal()`로 생성하지 않는다.
- `1xx`는 요청·입력값 오류, `2xx`는 인증·인가 오류, `3xx`는 리소스 오류, `4xx`는 비즈니스 오류, `5xx`는 HTTP 프로토콜 오류, `9xx`는 서버 내부 오류다.
- 오류 ID의 의미는 변경하거나 다른 오류에 재사용하지 않는다.
- 응답의 `status`는 실제 HTTP 상태 코드와 항상 같다.

## 기본 응답

일반 오류는 다음 세 필드만 반환한다.

```json
{
  "id": 301,
  "status": 404,
  "message": "요청한 리소스를 찾을 수 없습니다."
}
```

`message`는 `ProblemType.clientMessage`의 고정 공개 메시지이며, 서버 예외의 내부 메시지는 포함하지 않는다.

## 검증 오류 확장

검증 실패는 기본 세 필드에 `errors` 배열을 추가한다.

```json
{
  "id": 102,
  "status": 400,
  "message": "요청 값이 올바르지 않습니다.",
  "errors": [
    {
      "field": "email",
      "message": "이메일 형식이 올바르지 않습니다."
    }
  ]
}
```

`errors[].field`는 요청 필드명이고, `errors[].message`는 검증 규칙의 공개 메시지다. 입력값, rejected value, 내부 예외 메시지는 포함하지 않는다.

## 오류 목록

### 100번대 · 요청·입력값 오류

| ID | 이름 | HTTP 상태 | 공개 메시지 |
| ---: | --- | ---: | --- |
| 101 | `INVALID_REQUEST` | 400 | 요청 형식이 올바르지 않습니다. |
| 102 | `VALIDATION_FAILED` | 400 | 요청 값이 올바르지 않습니다. |

### 200번대 · 인증·인가 오류

| ID | 이름 | HTTP 상태 | 공개 메시지 |
| ---: | --- | ---: | --- |
| 201 | `AUTHENTICATION_REQUIRED` | 401 | 로그인이 필요합니다. |
| 202 | `AUTHENTICATION_FAILED` | 401 | 인증 정보가 올바르지 않습니다. |
| 203 | `ACCESS_DENIED` | 403 | 해당 요청을 수행할 권한이 없습니다. |

### 300번대 · 리소스 오류

| ID | 이름 | HTTP 상태 | 공개 메시지 |
| ---: | --- | ---: | --- |
| 301 | `RESOURCE_NOT_FOUND` | 404 | 요청한 리소스를 찾을 수 없습니다. |

### 400번대 · 비즈니스 오류

| ID | 이름 | HTTP 상태 | 공개 메시지 |
| ---: | --- | ---: | --- |
| 401 | `CONFLICT` | 409 | 요청이 현재 리소스 상태와 충돌합니다. |
| 402 | `UNPROCESSABLE_ENTITY` | 422 | 요청을 처리할 수 없습니다. |

### 500번대 · HTTP 프로토콜 오류

| ID | 이름 | HTTP 상태 | 공개 메시지 |
| ---: | --- | ---: | --- |
| 501 | `METHOD_NOT_ALLOWED` | 405 | 지원하지 않는 HTTP 메서드입니다. |
| 502 | `UNSUPPORTED_MEDIA_TYPE` | 415 | 지원하지 않는 미디어 타입입니다. |

### 900번대 · 서버 내부 오류

| ID | 이름 | HTTP 상태 | 공개 메시지 |
| ---: | --- | ---: | --- |
